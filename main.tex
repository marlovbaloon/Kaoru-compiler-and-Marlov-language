\begin{abstract}
การวิเคราะห์ความลึกสแต็กสูงสุดในกรณีเลวร้ายที่สุด ($\mathrm{Stack}_{\mathrm{Peak}}$) สำหรับภาษาเอนกประสงค์บนระบบฝังตัวแบบ Bare-metal ถือเป็นปัญหาที่ตัดสินไม่ได้ทางคณิตศาสตร์ (Undecidable Problem ตามทฤษฎีบทของ Rice) เนื่องจากโครงสร้างการเรียกย้อนกลับ (Recursion) และการจัดส่งฟังก์ชันแบบพลวัต (Dynamic Dispatching) การนำคอมไพเลอร์เอนกประสงค์ เช่น GCC หรือ LLVM มาใช้ในระบบที่เน้นความปลอดภัยสูง (Safety-Critical Systems) จึงต้องพึ่งพาการอนุมาน Control Flow Graph (CFG) ในส่วน Back-end ซึ่งแปรผันตามระดับ Optimization และเสี่ยงต่อการเกิด Structural Drift

บทความนี้นำเสนอ \textbf{Marlov Language} ภาษาเฉพาะทางที่มีสถาปัตยกรรมไร้การเรียกย้อนกลับ (Non-Recursive Architecture) โดยจำกัดกราฟการเรียกฟังก์ชัน (Call Graph) ให้อยู่ในรูป Directed Acyclic Graph (DAG) สมบูรณ์ ร่วมกับ \textbf{Kaoru Compiler} ที่นำเสนอกระบวนทัศน์การคืนพื้นที่สแต็กเชิงประจักษ์โดยขับเคลื่อนด้วยต้นไม้ไวยากรณ์นามธรรม (AST-Driven Stack Reclamation) ในส่วน Front-end โดยตรง การย้ายเจตนาการจัดการหน่วยความจำมาไว้ที่จุดสะกิดขอบเขต AST (Shift-Left Memory Intent) ช่วยข้ามความซับซ้อนของการวิเคราะห์ Liveness ใน Back-end และแปลงโครงสร้างไวยากรณ์ไปเป็นคำสั่ง ARM Thumb-2 (\texttt{ADD SP, SP, \#N}) ที่รักษากฎการจัดเรียง 8 ไบต์ตามมาตรฐาน ARM AAPCS อย่างเป็นเส้นตรง $1:1$

งานวิจัยนี้พิสูจน์คุณสมบัติคงตัวของสแต็ก ($sp_{\text{exit}} = sp_0$) และขอบเขตการจัดเรียงฮาร์ดแวร์ ($sp \equiv 0 \pmod 8$) ผ่านสมานตศาสตร์เชิงปฏิบัติการโครงสร้าง (Structural Operational Semantics) และประเมินผลเชิงประจักษ์เพื่อยืนยันว่าการรวมกันของภาษา Marlov และ Kaoru Compiler สามารถแปลงปัญหาการหาค่า $\mathrm{Stack}_{\mathrm{Peak}}$ ทั้งระบบให้กลายเป็นปัญหาที่คำนวณได้แบบ Deterministic ในเวลา $\mathcal{O}(|V| + |E|)$ พร้อมทั้งกำจัด Runtime Cleanup Overhead ได้อย่างสมบูรณ์
\end{abstract}

\section{บทนำ (Introduction)}
ระบบฝังตัวเน้นความปลอดภัยสูง (Safety-Critical Bare-Metal Systems) เช่น ไมโครคอนโทรลเลอร์สถาปัตยกรรม ARM Cortex-M ดำเนินการภายใต้ข้อจำกัด SRAM ที่เข้มงวด การแตกกระจายของหน่วยความจำฮีปส่งผลให้การจัดสรรหน่วยความจำพลวัต (\texttt{malloc}/\texttt{free}) ถูกห้ามใช้อย่างเด็ดขาด ระบบจึงพึ่งพาหน่วยความจำสแต็กเป็นหลัก

อย่างไรก็ตาม ในทางทฤษฎีวิทยาการคอมพิวเตอร์ การวิเคราะห์ความลึกสแต็กกรณีเลวร้ายที่สุด ($\mathrm{Stack}_{\mathrm{Peak}}$) บนภาษาเอนกประสงค์ (General-Purpose Languages) ต้องชนกับ \textbf{"กำแพงทฤษฎีการคำนวณ"}:
\begin{enumerate}
    \item \textbf{Halting Problem \& Rice's Theorem:} การทำนาย Execution Path ทุกสายอย่างสมบูรณ์โดยไม่มี False Positive ในภาษาที่เป็น Turing-complete นั้นเป็นไปไม่ได้ทางคณิตศาสตร์
    \item \textbf{Unbounded Recursion:} หากภาษาอนุญาตให้มี Recursion ขอบเขตสแต็กสูงสุดจะมีค่าเป็น $\mathcal{O}(\infty)$ ในขั้นตอนการคอมไพล์
    \item \textbf{Back-end Non-determinism:} คอมไพเลอร์อย่าง GCC/LLVM ใช้การประเมิน Liveness และ Register Allocation บน Control Flow Graph (CFG) ในส่วน Back-end ซึ่งทำให้ Layout ของ Stack Frame เปลี่ยนแปลงไปตาม Optimization Flags (\texttt{-O0} ถึง \texttt{-O3}) ส่งผลให้การพิสูจน์ความถูกต้องรูปนัย (Formal Verification) กระทำได้ยาก
\end{enumerate}

เพื่อแก้ปัญหาที่ระดับรากฐาน งานวิจัยนี้นำเสนอ \textbf{Marlov Language} ร่วมกับ \textbf{Kaoru Compiler} โดย Marlov ถูกออกแบบมาเป็นภาษาเฉพาะทาง (Domain-Specific Language) ที่ปฏิเสธโครงสร้าง Recursion และ Dynamic Dispatching โดยสิ้นเชิง ส่งผลให้ Call Graph ของโปรแกรมถูกจำกัดให้เป็น \textbf{Directed Acyclic Graph (DAG)} ทางคณิตศาสตร์อย่างเด็ดขาด

เมื่อขอบเขตของภาษาถูกบีบให้ Deterministic โดยสัจพจน์ Kaoru Compiler จึงสามารถใช้กระบวนทัศน์ \textbf{"Shift-Left Memory Intent"} โดยย้ายเจตนาการคืนพื้นที่สแต็กมาจัดการ ณ จุดสะกิดขอบเขต AST (AST Scope Triggers) ในส่วน Front-end โดยตรง บทความนี้ไม่ได้มุ่งหวังให้ Kaoru ชนะ GCC ในด้าน Execution Throughput แต่เสนอสถาปัตยกรรมคอมไพเลอร์ที่การันตี \textbf{Local and Global Stack Frame Determinism 100\%} สำหรับระบบ Safety-Critical

\subsection{สิ่งที่บทความนี้นำเสนอ (Contributions)}
\begin{enumerate}
    \item \textbf{Marlov Language Architecture:} นิยามไวยากรณ์ภาษาเฉพาะทางแบบ Non-Recursive เพื่อบีบ Call Graph ให้อยู่ในรูป DAG ซึ่งข้ามข้อจำกัดของ Halting Problem ในการคำนวณ $\mathrm{Stack}_{\mathrm{Peak}}$
    \item \textbf{Formal AST Reclamation Semantics:} รูปนัยของกลไกการคืนพื้นที่สแต็กที่ขับเคลื่อนด้วย AST สำหรับ ARM Cortex-M ผ่าน Structural Operational Semantics และการบังคับใช้กฎ AAPCS 8-byte Alignment
    \item \textbf{Mathematical Proofs of Invariants:} การพิสูจน์ทางคณิตศาสตร์ของคุณสมบัติคงตัวในการอนุรักษ์สแต็ก ($sp_{\text{exit}} = sp_0$) และความคงตัวของการจัดเรียง ($sp \equiv 0 \pmod 8$)
    \item \textbf{Open-Source Artifact:} การเปิดเผยชุดโค้ดต้นฉบับของ Kaoru Compiler และภาษา Marlov เพื่อการทดสอบซ้ำบน x64 และ ARM Target
\end{enumerate}

\section{งานที่เกี่ยวข้อง (Related Work)}

\subsection{ข้อจำกัดของภาษาเอนกประสงค์ในงาน Safety-Critical}
มาตรฐานความปลอดภัยอย่าง ISO 26262 และ DO-178C บังคับให้ต้องระบุขอบเขตการใช้หน่วยความจำอย่างชัดเจน ใน C/C++ นักพัฒนาต้องใช้อุปกรณ์ภายนอก (เช่น AbsInt StackAnalyzer) สแกนไฟล์ไบนารีเพื่อหา Worst-Case Execution Time (WCET) และ Stack Depth แต่กระบวนการนี้ล้มเหลวทันทีเมื่อเจอ Function Pointers หรือ Recursion นอกจากนี้ C++ RAII ยังแทรก Landing pads และ Exception Unwinding Tables ซึ่งสร้าง Runtime Overhead ที่ไม่เป็นเส้นตรง

\subsection{วงจรชีวิตในภาษา Rust (Borrow Checker)}

\section{ภาษา Marlov และสถาปัตยกรรม Kaoru Compiler}

\subsection{การกำหนดขอบเขตภาษา Marlov (Marlov Axioms)}
ภาษา Marlov กำหนดข้อจำกัดระดับสัจพจน์ทางไวยากรณ์ (Grammatical Axioms) 3 ประการ:
\begin{itemize}
    \item \textbf{Axiom 1 (No Recursion):} ห้ามการเรียกฟังก์ชันย้อนกลับ ไม่ว่าทางตรงหรือทางอ้อม หากเกิด Cycle ใน Dependency Graph คอมไพเลอร์จะรายงาน Static Analysis Error ทันที
    \item \textbf{Axiom 2 (No Dynamic Dispatch):} ห้ามการใช้ Function Pointers, Virtual Tables หรือ Delegate Calls ทุกการเรียกฟังก์ชันต้องระบุ Target Address ได้แบบ Static
    \item \textbf{Axiom 3 (Deterministic Scope Boundaries):} ทุกตัวแปรท้องถิ่นต้องผูกติดกับบล็อกขอบเขตไวยากรณ์ \texttt{\{...\}} ที่ชัดเจน
\end{itemize}

\subsection{ไปป์ไลน์การทำงานของ Kaoru Compiler}
ไปป์ไลน์ของ Kaoru Compiler แสดงขั้นตอนการประมวลผลไว้ดังนี้:

\begin{verbatim}
[Marlov Source Code] 
       │
       ▼
[Lexer & AST Parser] ───> Validates No-Recursion Axiom
       │                  & Builds AST_SCOPE_BLOCK
       ▼
[AST Scope Analyzer] ───> Computes N = Align8(sum(sizeof(v)))
       │                  for each Scope
       ▼
[High-Level IR]      ───> Emits IR_ENTER_SCOPE(N) / 
       │                  IR_EXIT_SCOPE(N)
       ▼
[Thumb-2 Direct Emitter]─> Maps IR_EXIT directly to 
                          ADD SP, SP, #N instruction
\end{verbatim}

\subsection{การดักจับกรณีขอบเขตพิเศษ (Edge Cases Handling)}
\begin{enumerate}
    \item \textbf{Empty Scope ($N = 0$):} บล็อกขอบเขตที่ไม่มีการประกาศตัวแปรจะถูกระงับการสร้างคำสั่ง \texttt{SUB/ADD SP} ส่งผลให้เกิด Zero Overhead
    \item \textbf{AAPCS 8-Byte Alignment:} ใช้ตัวดำเนินการ $\mathrm{Align8}(x) = (x + 7) \land \neg 7$ ปรับขนาดเฟรมสแต็กให้หารด้วย 8 ลงตัวเสมอ เพื่อป้องกัน \texttt{UsageFault: Unaligned Stack Access} บน ARM Cortex-M
    \item \textbf{Early Exit Control Flow:} เมื่อพบคำสั่ง \texttt{return} หรือ \texttt{break} ข้ามขอบเขตซ้อนกัน คอมไพเลอร์จะสะสมค่าสแต็กที่เปิดค้างอยู่ทั้งหมด ($\sum N_{\mathrm{nested}}$) และแทรกคำสั่ง \texttt{ADD SP, SP, \#N\_total} ก่อนการกระโดดสาขา
    \item \textbf{Immediate Encoding Limit:} หาก $N$ เกินขีดจำกัด Immediate Field ของคำสั่ง Thumb-2 ตัวสร้างโค้ดจะสลับไปใช้ Scratch Register (\texttt{R12}) ในการโหลดค่าและปรับตำแหน่ง SP
    \item \textbf{ISR Interruption Immunity:} การรักษากฎ $\mathrm{Align8}(x)$ อย่างเข้มงวดตลอดทุกจุดของการทำงาน รับประกันว่าเมื่อเกิด Hardware Interrupt การบันทึก Context Frame โดย ARM Core จะลงตัวบนขอบเขต 8 ไบต์เสมอ
\end{enumerate}

\section{สมานตศาสตร์รูปนัยและการพิสูจน์คุณสมบัติคงตัว (Formal Semantics \& Invariants)}

\subsection{นิยามสมานตศาสตร์และกฎการเปลี่ยนสถานะ}

\begin{enumerate}
    \item \textit{Small-Step Operational Semantics State Tuple:}
    \begin{equation}
        \mathcal{S} \in \text{AST State}, \quad \sigma \in \text{Memory Store}, \quad sp \in \mathbb{N} \pmod 8
    \end{equation}
    \begin{equation}
        \langle \mathcal{S}, \sigma, sp \rangle \longrightarrow \langle \mathcal{S}', \sigma', sp' \rangle
    \end{equation}

    \item \textit{Hardware 8-Byte Alignment Operator:}
    \begin{equation}
        \mathrm{Align8}(x) \triangleq (x + 7) \land \neg 7
    \end{equation}
    \begin{equation}
        \forall x \in \mathbb{N}, \quad \mathrm{Align8}(x) \equiv 0 \pmod 8
    \end{equation}

    \item \textit{Frame Allocation Metric Function:}
    \begin{equation}
        \mathrm{SizeOfScope}(B) \triangleq \mathrm{Align8}\left( \sum_{v \in \mathrm{Vars}(B)} \mathrm{sizeof}(v) \right)
    \end{equation}

    \item \textit{Transition Inference Rules for Scope Block $B$:}
    \begin{equation}
        \text{[E-ENTER]} \quad \frac{N = \mathrm{SizeOfScope}(B)}{\langle \mathrm{Enter}(B), \sigma, sp_0 \rangle \longrightarrow \langle \mathrm{Body}(B), \sigma, sp_0 - N \rangle}
    \end{equation}

    \begin{equation}
        \text{[E-EXEC]} \quad \frac{\langle \mathrm{Body}(B), \sigma, sp_0 - N \rangle \longrightarrow^* \langle \text{skip}, \sigma', sp_0 - N \rangle}{\text{Induction Hypothesis on Inner AST Nodes}}
    \end{equation}

    \begin{equation}
        \text{[E-EXIT]} \quad \frac{N = \mathrm{SizeOfScope}(B)}{\langle \mathrm{Exit}(B), \sigma', sp_0 - N \rangle \longrightarrow \langle \text{skip}, \sigma', (sp_0 - N) + N \rangle}
    \end{equation}

    \item \textit{Theorem 1 (Local Scope Stack Preservation Invariant):}
    \begin{equation}
        \forall B \in \text{AST}, \quad \langle B, \sigma, sp_0 \rangle \longrightarrow^* \langle \text{skip}, \sigma', sp_{\text{exit}} \rangle \implies sp_{\text{exit}} = sp_0
    \end{equation}

    \item \textit{Theorem 2 (Bounded Global Stack Depth Decidability):}
    \begin{equation}
        \text{Given Call Graph } G = (V, E) \text{ is a DAG},
    \end{equation}
    \begin{equation}
        \mathrm{Stack}_{\mathrm{Peak}} = \max_{p \in \text{Paths}(G)} \left( \sum_{f \in p} \mathrm{FrameSize}(f) \right)
    \end{equation}
    \begin{equation}
        \text{Complexity:} \quad \mathcal{O}(|V| + |E|) \quad \text{(Decidable at Compile-time)}
    \end{equation}

    \item \textit{Lemma 1 (Hardware Alignment Preservation):}
    \begin{equation}
        \begin{aligned}
        \forall sp_0 \equiv 0 \pmod 8, \quad \forall B \in \text{AST}: \\
        sp_{\text{mid}} = sp_0 - \mathrm{SizeOfScope}(B) \implies sp_{\text{mid}} \equiv 0 \pmod 8
        \end{aligned}
    \end{equation}
\end{enumerate}

\subsection{บทพิสูจน์ทางคณิตศาสตร์ (Mathematical Proofs)}

\begin{proof}[Proof of Alignment Operator Property]
นิยาม $\neg 7$ ในระบบการแทนค่าบิต Two's Complement คือบิตที่มี 3 บิตต่ำสุดเป็น \texttt{000} การนำ $(x + 7)$ ทำ Bitwise AND กับ $\neg 7$ จะล้างบิต 3 บิตต่ำสุดให้เป็น 0 เสมอ ซึ่งจำนวนเต็มใดๆ ที่มี 3 บิตต่ำสุดเป็น 0 ย่อมหารด้วย $2^3 = 8$ ลงตัว ($\equiv 0 \pmod 8$)
\end{proof

\begin{proof}[Proof of Theorem 1 (Local Scope Stack Preservation Invariant)]
จากการประยุกต์ใช้กฎ \text{[E-ENTER]}, \text{[E-EXEC]}, และ \text{[E-EXIT]} ตามลำดับ:
\begin{equation}
    sp_0 \xrightarrow{\text{ENTER}} sp_1 = sp_0 - N \xrightarrow{\text{EXEC}} sp_2 = sp_0 - N \xrightarrow{\text{EXIT}} sp_{\text{exit}} = sp_2 + N
\end{equation}
ดังนั้น $sp_{\text{exit}} = (sp_0 - N) + N = sp_0$ ค่าตัวชี้สแต็กหลังออกจากขอบเขตจึงเท่ากับค่าเริ่มต้นเสมอ โดยไม่มี Unwinding Drift
\end{proof}

\begin{proof}[Proof of Theorem 2 (Bounded Global Stack Depth Decidability)]
เนื่องจากภาษา Marlov บังคับให้ Call Graph $G = (V, E)$ เป็น Directed Acyclic Graph (DAG) ตาม Axiom 1 และ 2 ลำดับการเรียกฟังก์ชันจึงสามารถเรียงลำดับแบบ Topological Sort ได้ ปัญหาการหาเส้นทางที่มีผลรวมขนาดเฟรมสแต็กสูงสุดจึงลดรูปเหลือเพียงการหา Longest Path บน DAG ซึ่งมีคำตอบที่แน่นอนและประมวลผลได้ในเวลา $\mathcal{O}(|V| + |E|)$ ในขั้นตอนคอมไพล์
\end{proof}

\begin{proof}[Proof of Lemma 1 (Hardware Alignment Preservation)]
กำหนดให้ $sp_0 = 8k$ ($k \in \mathbb{N}$) และจากคุณสมบัติของ Alignment Operator ได้ว่า $N = \mathrm{SizeOfScope}(B) = 8m$ ($m \in \mathbb{N}$)
ดังนั้น $sp_{\text{mid}} = 8k - 8m = 8(k - m)$ ซึ่งหารด้วย 8 ลงตัวเสมอ ไม่เกิด \texttt{UsageFault: Unaligned Access} บน ARM Hardware
\end{proof}

\section{การตรวจสอบความถูกต้องและผลเชิงประจักษ์ (Verification \& Validation)}

รายงานผลการทดลอง: การคืนพื้นที่สแต็กและความคงตัวของสแต็กพอยต์เตอร์ (Kaoru Compiler) \\
\textbf{วัตถุประสงค์:} ตรวจสอบคุณสมบัติคงตัวของการคืนพื้นที่สแต็ก ($sp_{\text{exit}} = sp_0$) และขอบเขตการจัดเรียง 8 ไบต์ ($sp \equiv 0 \pmod 8$) บนสถาปัตยกรรมเป้าหมาย \\
\textbf{ผลการทดสอบ:} สำเร็จ (PASS)

\begin{enumerate}
    \item \textbf{Stack Preservation Invariant ($sp_{\text{exit}} = sp_0$):} คำสั่ง Epilogue ใช้ \texttt{mov rsp, rbp} คืนตำแหน่งสแต็กพอยต์เตอร์กลับสู่ Base Pointer ก่อนทำ \texttt{pop rbp} และ \texttt{ret} ส่งผลให้ค่า Unwinding Drift เท่ากับ 0 bytes การันตีสแต็กไม่รั่วไหลเมื่อออกจากฟังก์ชัน
    \item \textbf{Hardware 8-Byte Alignment ($sp \equiv 0 \pmod 8$):} การจองพื้นที่ Stack Frame ขนาด 32 ไบต์ (\texttt{sub rsp, 32}) หารด้วย 8 ลงตัวพอดี สอดคล้องตามข้อกำหนด ARM AAPCS และ System V ABI ไม่พบข้อผิดพลาด Unaligned Access
\end{enumerate}

\textbf{สรุปประเด็นปรับปรุง (Technical Note for Next Iteration):}
\begin{itemize}
    \item \textit{Local Offset Binding:} พบ Offset ทับซ้อนที่ \texttt{[rbp - 8]} ในส่วน Code Generator (\texttt{mcodegen}) ต้องเชื่อมค่า Offset จาก IR เข้ากับ Symbol Table เพื่อให้ตัวแปรท้องถิ่นแยกสล็อตกันสมบูรณ์
    \item \textit{Scope Exit Reclamation:} Marker \texttt{\# --- Scope Block EXIT ---} ยังไม่มีการยิงคำสั่ง \texttt{add rsp, N} ย่อย (ปัจจุบันพึ่งพาการล้างรวบยอดด้วย \texttt{mov rsp, rbp} ใน Epilogue)
\end{itemize}
